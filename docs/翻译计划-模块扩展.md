# Micronaut 文档模块扩展翻译计划（M4：core 之外的官方模块）

> 状态: v1.0 生效（2026-11-21 制定，经三轮复审修订——R1 技术完整性 / R2 口径一致性 / R3 端到端对抗，修正 15 项）｜ 决策: DR-006（同仓库聚合架构）｜ 本文件是模块扩展范围的权威规范；流程章节（SOP/门禁/纪律）沿用 `docs/翻译计划.md` v1.1，不复制不改写。

## 0. 一句话定位

在 micronaut-zh-docs 单仓库内，对官方站 `/5.2.x/` 聚合站下除 Core 外的 ~71 个模块文档（分散于 micronaut-projects 各模块独立仓库的 `src/main/docs/`）按优先级分层翻译，聚合到现有单页站（模块切换导航），沿用 core 全套管线与纪律。

## 1. 范围与总量

- 官方导航 73 条目 = 71 个 docs.micronaut.io 托管模块 + 2 个外链（Maven 插件、Platform，**不在本计划**，后续单议）。Pulsar/Tracing 跨组重复引用按去重计。
- 体量（抽样外推，各模块开工时 inventory 精算）：**~2600 页 / 30–40 万词 / ~250–300 批 / 10–14 个翻译会话**（约为 core 的 2 倍）。
- 结构核实（security 样本）：与 core 完全同构——`src/main/docs/guide/toc.yml + *.adoc + 子目录 + resources/`，存在 0 字节壳文件（skipped 机制直接复用）。

## 2. 仓库架构（DR-006：同仓库聚合）

```
micronaut-zh-docs/
├── manifest.yml            # core 账本（不动，388 条目）
├── manifests/<site>.yml    # 每模块独立账本（schema v1；顶层加 ref/locked_at 字段）
├── source/guide/           # core 快照（不动）
├── source/modules/<site>/  # 模块快照（guide/ + toc.yml + resources/，仅 .adoc+图片入库）
├── zh/guide/               # core 译文（不动）
├── zh/modules/<site>/      # 模块译文 1:1 镜像
└── build/site/             # index.html(core) + <site>.html × 模块 + landing.html
```

- **core 现状零迁移**：source/zh/manifest 不动，`core-` 锚与 URL 不变。
- 模块 manifest 的 file/zh 字段写全相对路径 `modules/<site>/guide/x.adoc` → segment/protect/validate/assemble/mark-current **零改动复用**（按账本字段操作）。
- 仓库体积对策：模块图片跟随该模块快照才入库；M4.0 试点实测图片总量，>300MB 则启用 git-lfs（.gitattributes，试点验收项）。

## 3. 优先级分层（P0→P5）

| 层 | 模块 | 会话估算 |
|---|---|---|
| **P0 安全与观测**（首批） | security★(24 章，多会话)、validation、hibernate-validator、micrometer（试点）、tracing、session | 3–4 |
| **P1 数据与消息**（17） | data★、sql、r2dbc、mongodb、redis、neo4j、cassandra、coherence、eclipsestore、liquibase、flyway、kafka、rabbitmq、nats、jms、pulsar、mqtt | 5–6 |
| **P2 API 与集成**（11） | openapi★、graphql、grpc、serde、jackson-xml、json-schema、spring★、jaxrs、servlet、guice、jakarta-el | 4 |
| **P3 云与部署**（10） | aws★、gcp★、azure、kubernetes、oracle-cloud、object-storage、discovery-client、aot、crac、acme | 4 |
| **P4 语言与测试**（6） | kotlin、groovy、graal-languages、test、test-resources、control-panel | 3 |
| **P5 长尾**（~20） | views、rss、multitenancy、toml、logging、problem-json、elasticsearch、opensearch、picocli、email、chatbots、cache、rxjava3、reactor、jmx、http、sourcegen、openrewrite、projectgen、langchain4j、mcp | 4 |

★ = 头部模块（≥40 页），单独 2–3 会话、按章节化批次推进。层间收尾打 tag（v1.1–v1.6）。

## 4. 模块 SOP（在 PLAN §5.1 七步基础上追加模块步骤）

1. **snapshot**：`sync_upstream.py --repo micronaut-projects/<repo> --doc-root src/main/docs --manifest manifests/<site>.yml --ref <分支>`（分支：优先 5.2.x，缺失用默认分支；账本顶层记录 `ref` + `locked_at`）；快照仅 guide/.adoc + toc.yml + resources 图片入库。
2. **首检**：toc.yml 存在性（缺失 → 按 inventory 目录树生成伪 toc + 人工核对标记）；0 字节壳标 skipped；`--collect-commits` 延后到批次首日（限流对策）。
3. **inventory**：模块版切批（双指标非代码词 ≤3500），批次编号 `<模块大写>-<序号>`（SEC-01、DATA-01…），报告 `reports/batch-SEC-01.md`。
4. **批次翻译**：PLAN §5.1 七步全流程；锚点前缀 `<site>-<basename>`（与官方模块站互通，如 security-introduction）。
5. **核销与渲染**：validate ①–⑦ 全绿 → `--mark-current`（模块 manifest）→ `render.mjs --module <site>` 上线。
6. **术语作用域**：glossary.yml 新增 `modules:` 分节（术语带 `module: <site>` 标注）；validate ③ 扫描集 = 通用 terms + 当前模块术语（防跨模块回流，B22 教训）；core 批次不含模块专属术语。

## 5. 脚本改造（M4.0，core 缺省行为不变）

| 脚本 | 改造 |
|---|---|
| sync_upstream.py | 模块常量 UPSTREAM_REPO/UPSTREAM_DOC → `--repo`（已有）+ 新增 `--doc-root`、`--manifest`，贯穿 gh api 路径/sparse-checkout/manifest 读取 |
| inventory.py | `--manifest` + toc 路径参数化（现写死 source/guide/toc.yml） |
| progress.py | 多 manifest 聚合汇总，按模块分组输出 |
| validate/segment/protect/assemble | 零改动（按账本全路径字段工作），仅 pytest 补模块路径回归用例 |
| render.mjs | 读 modules.json（site/repo/title 清单）逐模块产 `<site>.html`（`--anchor-prefix <site>`、imagesdir=modules/<site>/img/）；core 的 index.html 与 `core-` 锚不动；新增 landing.html（复刻官方 `/5.2.x/` 分组导航）与顶部模块切换条 |
| 新增 check_all.sh | 遍历 modules.json 串行逐模块 `--check`，汇总表 + 异常仓报告（~5 分钟/轮） |

## 6. 同步与版本基线

- 周同步扩为逐模块批量 `--check`（check_all.sh）；issue 命名 `[upstream-sync][<site>] <sha>: 同步待处理`。
- 优先级规则：**core 增量复译（issue 48h 目标）优先于模块新批次**；同会话不混排。
- 各模块基线 = 首个快照日统一锁定的实际 ref HEAD；5.3.x 全家族切换届时单独决策。

## 8. 风险登记

| # | 风险 | 对策 |
|---|---|---|
| 1 | 模块文档结构差异（无 toc/层级异常） | snapshot 后首检 + 伪 toc 回退 + 人工核对 |
| 2 | 图片体量失控 | 试点实测 + LFS 决策项 + 按需入库 |
| 3 | 跨模块术语回流 | glossary `modules:` 分节 + validate ③ 模块化扫描集 |
| 4 | 分支策略不统一（kafka 无 5.2.x） | 账本记录实际 ref + locked_at；check 按各模块 ref |
| 5 | 模块间/指向官方的跨站链接 | 保持指向官方站原样（DR-005 已知差异），站内互链列可选增强 |
| 6 | gh api 限流（upstream_commit ~1500 次） | collect-commits 延后 + 缓存 + 可延后机制 |
| 7 | 单仓 git 体积 | 按需快照 + LFS 备选；build/ 不入库 |

## 9. 已知差异与不执行范围

- 内容标题层级较官方深一级（官方 Astro 零偏移拼接，asciidoctor 无法复现；DR-005 记录）——导航/锚点/跳转不受影响。
- 模块间互链保持官方站绝对链接原样。
- 不执行：Maven/Platform 外链模块、guides 二期（另行立项）、5.3.x 基线切换（届时单独决策）。
