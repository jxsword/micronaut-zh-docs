# Micronaut 官方文档中文翻译计划（micronaut-zh-docs）

> 状态: v1.1 生效（2026-11-19 制定并经三轮复审修订，变更见附录 C）｜本文件是本工程**唯一权威规范**：所有会话开工前必读；修改架构类内容属重大决策，须经 `docs/decision_log.md` 记录。
> 决策记录: DR-001（范围分期）、DR-002（.adoc 直译）、DR-003（暂不建站），见附录 A。

## 0. 一句话定位

对 Micronaut 官方文档（docs.micronaut.io 主指南）做**社区非官方中文翻译**：agent 分批翻译、git 管理、上游 blob-sha 账本驱动增量同步与增量翻译；一期只做主指南，guides 站立二期。

## 1. 项目定位与范围

### 1.1 定位与免责

- 非官方项目：与 Micronaut 团队（Object Computing / micronaut-projects）无隶属关系；可能有滞后，冲突时以官方英文文档为准；译文问题欢迎提 issue。
- 署名遵循 TASL 四要素（Title/Author/Source/License），上游许可 Apache-2.0，见 `LICENSE_TRANSLATION.md`（M0 建仓时产出）。
- 版本基线（轻量决策，随 DR-001 记录）：初译基线锁定 **5.2.x 线 tag `v5.2.25`**（2026-11-17 发布，与 docs.micronaut.io/5.2.x/ 在线内容一致；注意 versions.json 标签滞后，实际版本以在线页头徽标为准）。

### 1.2 一期范围（本工程）

- 上游：`micronaut-projects/micronaut-core` 分支 `5.2.x`、tag `v5.2.25` 的 **`src/main/docs/` 全量**（386 个 .adoc ≈ 872KB ≈ 11 万词，其中纯散文估 6–8 万词；`resources/` 图片；`toc.yml` / `toc-python.yml`）。
- 在线对照物：https://docs.micronaut.io/5.2.x/（跳转至 /5.2.x/core/，单页 HTML ≈ 11.4MB，页头徽标 Core v5.2.25）。
- `toc.yml` / `toc-python.yml`：M1 实测是否含供页面显示的标题文本；若有，标题纳入翻译（页面路径与文件名不译），并纳入 validate 结构检查。

### 1.3 二期范围（预留，开工前须新决策）

- 上游：`micronaut-projects/micronaut-guides`（`guides/` 下 199 目录 = 196 篇正文 + 3 个 `*-base` 模板，681 个 .adoc ≈ 15.6 万词）。
- ⚠️ License 不同：guides 内容为 **CC-BY-4.0**，署名要求与一期分开处理；每篇 guide 附 6 语言代码工程，同步切分复杂度更高，须单独规划批次。
- **官方站模块文档扩展（core 之外 ~71 个模块）见独立计划 `docs/翻译计划-模块扩展.md`（DR-006，M4 起）**——本文件 §1.2 一期范围不含模块文档。

### 1.4 明确不译

- 全部代码块、行内代码、API 名、配置 key、flag、URL、`[[显式锚点]]`、`source::/source[]/include::[]` 等指令行、版本号、依赖坐标；
- API javadoc 参考文档（一期不含 API 站点）；
- `/snapshot/` 开发版文档。

## 3. 总体架构与目录结构

蓝本来源：目录与工作流对齐家族工程——以 spdlog-zh-docs 为主蓝本（docs/ 四件套、批次纪律），上游账本采用 google-benchmark 的 manifest 模式（文件级 blob sha + 四态状态机，OOM 加固版），双 agent 校对参考 google-test。

```

├── LICENSE                    # 本仓库许可 MIT（对齐 fmt/spdlog）
├── LICENSE_TRANSLATION.md     # 上游原文 Apache-2.0 与署名声明（M0）
├── .gitignore                 # .mimosa/ .venv/ __pycache__/ *.bak 等
├── manifest.yml               # 上游账本（唯一状态源，只允许脚本读写）——benchmark schema v1
├── source/                    # 上游英文快照（只读，仅 sync 写入；普通文件入库，不用 submodule）
│   ├── _upstream_commit       # 40 位 tag/commit sha（M1 起由脚本写入，禁手抄）
│   ├── guide/                 # src/main/docs/guide 全量 .adoc（保留相对结构）
│   ├── resources/             # 上游图片镜像
│   └── toc.yml

│   ├── guide/…                # 每文件页头注入溯源引用块 + HTML 注释投影（见 5.4）
```

## 4. 上游同步与增量翻译机制

### 4.1 快照与账本

- 快照方式（M1 执行，不 submodule）：
  `git clone --depth 1 --filter=blob:none --branch v5.2.25 --sparse https://github.com/micronaut-projects/micronaut-core` →
  `sparse-checkout set src/main/docs` → 复制 `src/main/docs/**` 入 `source/`（guide/、resources/、toc.yml 及实测存在的其余文件，全量快照）。
- 账本 `manifest.yml`（benchmark schema v1，**唯一状态源**）：顶层 `upstream.baseline_commit` + `snapshot_date`；每文件 `blob_sha`（git blob sha，本地 `git hash-object` 可复算）、`size`、`status`（**current / stale / partial / missing** 四态）、`zh`、`paragraphs`、`updated_at`。`source/_upstream_commit` 与账本顶层字段由脚本同批写入（禁手抄）。
- 每文件 `upstream_commit`（署名与追溯用）：经 GitHub commits API `?path=<file>&sha=5.2.x&per_page=1` 采集；已认证限流下 386 次调用可行，须串行+本地缓存；失败可延后补采，不阻塞 M1 验收。

### 4.2 sync_upstream.py 命令面（移植 benchmark，含 OOM 三项审查）

| 命令 | 作用 |
|---|---|
| `--init` | 建账本，幂等 reconcile |
| `--check` | 比对上游（sparse 浅克隆到 `.upstream/`，gitignored，参照 **5.2.x 分支 HEAD**），更新四态，产出变更清单 |
| `--apply` | 把变更写入 `source/`，生成**增量工作项**（`reports/sync-<date>-<sha8>.md`）；**初译期（v1.0 前）门控禁用**，仅允许 `--check` + 开 issue（见 4.4） |
| `--mark-current FILE` | 修订收尾核销：要求译文溯源 hash+commit 双字段同时更新，否则拒绝 |
| `--dry-run` / `--file` / `--repo` | 辅助参数 |

退出码约定：0=无变更 / 1=有变更待翻译 / 2=环境错误（供 CI 判断）。运行一律 `memgate 2048 python3 scripts/sync_upstream.py …`。

### 4.3 增量判定与段落迁移

- 文件级：上游 `blob_sha` 不变 → current（跳过）；变化 → stale，生成工作项。
- 段落级（工作项内）：`segment_adoc.py` 对新旧 .adoc 与译文做三方比对，产出 `added / removed / kept_translated` 三分类——**只重译变更段，保留已译段**；改名文件按重合率 >80% 提示迁移；上游删除的文件，其 source 副本与译文一并移入 `archive/<日期>/`（不删除，保留追溯）；0 字节或纯 include 壳文件标记 `skipped`，不进批次。
- 段落 id：`{file}-{type}-{index}`，hash=sha256[:16]；写 `.bak` 备份后再动账本。

### 4.4 基线锁定策略

- **初译期（tag v1.0 之前）**：上游变更只检测、只开 issue（`[upstream-sync] <sha>: 同步待处理`），`--apply` 被门控禁用，不进入翻译流水，避免批次目标漂移；
- **冻结窗口**：任何翻译批次进行期间禁止 `--apply`（防止 source/ 在批次中途变化）；检测到的变更统一在批次收尾后处理并在看板记录；
- v1.0 之后：cron 检测 → 自动开 issue → 按 4.3 增量复译；
- 5.3.x 正式发布后是否切换基线：届时按重大决策走 decision_log。

## 5. 翻译流程与质量门禁

### 5.1 单批次 SOP（每批次一个 agent 会话或一对 agent）

1. 读 `docs/翻译计划.md` + `docs/handoff-latest.md` + 看板，认领批次；
2. `memgate 2048 python3 scripts/protect_untranslatable.py --file <files>` 生成受保护文本；
3. translator agent 翻译（prompt = 术语表全文 + style-guide + 硬性规则 + 受保护文本）；发现新术语先写回 glossary.yml 再继续；
4. 还原占位符 → reviewer agent 五项检查（漏译/多译逐段对照、术语一致、代码块逐字节 diff、链接锚点可达、溯源元数据一致）；
5. `memgate 2048 python3 scripts/validate_translation.py --file …` 全绿 → `--mark-current` 核销；
6. 每批次一个 squash commit（message 含批次号/段数/词数/上游日期）+ 批次报告 `reports/batch-<N>.md`；
7. 更新看板与 handoff。

批次规模（gtest 双指标）：**非代码词 ≤3500 且总词 ≤5500**。词数口径：对源文件先跑占位符保护，再按英文词计数（`wc -w` 等价）；「非代码词」= 剔除代码块与被保护片段后的计数；最终批次数以 M1 `reports/inventory-5.2.25.md` 实测切分为准，不以本计划估算数为准。同一文件严禁两个 agent 并发写；agent 并发上限取串行 1（spdlog 实测结论）。

### 5.2 占位符保护清单（asciidoc 特有，M1 实现并测试）

保护并替换为 `{{PROTECTED_<TYPE>_<HASH>}}`：`include::[]`、`xref::[]`、`link:[]`、`source::[]`/`source[]`、`ifdef/ifndef/ifeval/endif`、行内 `code`、URL、显式锚点 `[[id]]`、属性定义行（`:name: value`）、admonition 标记、表格对齐符。
CLI 双子命令：`--protect <files>` 生成受保护文本与映射表；`--restore` 按 HASH 完整还原并校验无残留/无丢失（哈希完整性纳入 validate 门禁）。
代码注入宏（`source::…`）在译文页保留原样，页尾追加「> 💡 本节代码示例与配置属性表见官方站对应章节（附 URL + 锚点）」对照提示（DR-003 配套）。

### 5.3 不译清单（硬性）

见 1.4 节；另加：语言切换宏（Java/Kotlin/Groovy/Python 代码标签）、`toc` 指令、`ifndef::env-github[]` 类环境条件块整体保留。

### 5.4 译文溯源投影（每文件）

每文件两层投影：
1. 页头引用块（人读，spdlog 式）：`> 本文翻译自 Micronaut Core v5.2.25 官方文档 [Guide – <页名>](官方对应 URL)，翻译基线锁定于 2026-11-19，非官方译文，以英文原文为准。`
2. 引用块后的 HTML 注释（机读，gtest 式四项，`--mark-current` 的校验对象）：
   `<!-- upstream_file: guide/<相对路径>  upstream_commit: <40位sha>  upstream_hash: <blob sha>  translated_at: <YYYY-MM-DD> -->`
修订收尾须注释内 hash+commit 双字段与 manifest 同步更新，缺一 `--mark-current` 拒绝核销。

### 5.5 validate 硬门禁（禁止 `|| true` 软门禁）

① 占位符全部还原且 hash 一致；② 代码块/指令行与上游逐字节一致；③ banned 黑名单 0 命中 + 必译术语命中检查；④ 结构对齐（标题层级树与上游逐级比对：层级数与顺序一致，标题文本已译）；⑤ xref/锚点目标存在（未译文件目标列入豁免清单，全量完成后清零）；⑥ 溯源投影字段齐全且与 manifest 一致；⑦ 风格机检子集（中英文空格、全角标点、禁繁体、邻接规则——标记后不得紧跟全角开括号；校验范围天然豁免 PROTECTED 占位符与代码块）。

### 5.6 锚点防漂移（asciidoc 特有风险）

上游被跨页引用的标题若仅依赖自动锚点，译文标题会改变自动 id → M1 产出 `check_anchors.py` 扫描全量 xref 目标锚点，登记到 **`config/anchor-registry.yml`**（被引用锚点 → 所在文件/标题）；translator prompt 必读该登记表，翻译时对被引用标题**原位注入 `[[原锚点]]` 显式锚点**，保持官方站锚点可对应；validate ⑤ 依登记表机检。

## 6. 术语与风格

- `config/glossary.yml`（M1 初稿，翻译中滚动修订，先写回再继续）：首批必收术语——compile-time dependency injection 编译期依赖注入、BeanContext（不译）、bean definition、AOT/AOP（保留）、IOCN（不译）、configuration properties 配置属性、interceptor 拦截器、BeanLifecycle、executable method、Serverless（保留）、GraalVM native image、reactive 响应式、netty（不译）、classpath 等；`banned:` 起步收录具体条目（M1 定稿并联动 validate 黑名单），示例：compile-time 不得译「编译时间」（须「编译期」）；BeanContext 不得译「Bean 上下文环境/Bean 环境」；禁止「类似 Spring 的 IoC」等类比表述进入译文正文（译者注须显式标记）。
- `config/style-guide.md`（spdlog 版为蓝本 + asciidoc 纪律）：中英文间空格、全角标点、禁繁体、语义等价不增不减、邻接规则、争议处理流程（先查术语表 → 编排方裁决 → 写回）。
- 机器可扫：glossary 校验并入 validate 门禁（对齐 fmt/spdlog 做法）。

## 7. git 与 CI

- 分支：主干 main 直推；sync 独立分支 `sync/<date>-<sha>`；无 PR 门槛时本地直推 + CI 校验兜底。
- commit 约定：conventional 前缀（docs/feat/fix/chore/sync/translation/review）；每批次一个 squash commit，决策类提交末行 `Decision: DR-编号`；决策日志随对应改动同 commit 入库。
- tag：全量完成并演练通过后打 `v1.0`（作为初译期基线锁定的解除开关，对齐 libuv/spdlog）。
- CI（M1 建文件；**远程仓库建立前 workflows 仅为预备件，本地门禁以直接运行 scripts/ 各校验命令为准**，生效依赖后续远程托管）：
  - `validate.yml`：PR/push 跑 pytest + validate + 快照清单冒烟；
  - `sync-upstream.yml`：每周一 UTC 02:00 + 手动 dispatch；初译期只开 issue；
  - deploy/建站 workflow：后置（DR-003），建站时另立决策。
- 远程仓库：暂不创建（本机 git 管理起步）；需要公开托管时另议（届时 README 免责与 Pages 配置一并做）。

## 10. 会话纪律（继承家族 spdlog handoff §7）

1. 一切以本计划为准；改架构属重大决策 → decision_log；
2. 所有脚本/构建 memgate 包裹；构建产物与临时克隆出仓库树或 gitignore；
3. `source/` 只读（仅 sync 写入）；`manifest.yml` 禁人工直改；
4. 门禁硬性化，禁止 `|| true`；
5. 每批次一个 squash commit + 批次报告（含实际词数）；
6. 子代理声明不可信，关键结论以编排方亲跑为准；
7. 上下文过半或里程碑收尾，主动建议开新会话并产出交接。
