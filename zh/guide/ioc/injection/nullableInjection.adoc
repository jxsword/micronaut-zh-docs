有时希望注入是可选的（即当没有可用的候选 bean 时，不因 api:context.exceptions.NoSuchBeanException[] 而失败）。

例如，如果您试图构建一个可扩展的系统：类型本身提供了默认实现，而 API 的使用者可以提供一个 bean，如果该 bean 可用，它将被注入。

[.lang-java.lang-groovy]
--
使注入变为可选的一种方式是使用 `org.jspecify.annotations.Nullable` 对注入的类型进行注解，这样当 bean 不可用时，框架将注入 `null`：

[.lang-java.lang-groovy]
--
使用 `org.jspecify.annotations.Nullable` 有以下注意事项：

* 可用于任何注入类型（构造器注入、方法注入或字段注入）
* 代码必须在某处处理注入 `null` 时会发生什么。对构造器而言这很容易，因为构造器可以处理 `null`；而对字段和方法，如果 `null` 不合期望，则需要实现一个 `@PostConstruct` 方法来处理 `null`。
* 最后，在使用 <<valueAnnotation, 配置注入>> 时，`@Nullable` 不能用于 `int`、`long` 等基本类型。要处理基本类型，您需要指定 `@Bindable(defaultValue="..")` 并提供默认值。
