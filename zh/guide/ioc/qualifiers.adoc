[[qualifiers]]
如果要注入的给定接口存在多个可能的实现，您需要使用限定符（qualifier）。

Micronaut 框架同样利用 JSR-330 以及 link:{jakartaapi}/jakarta/inject/Qualifier.html[Qualifier] 和 link:{jakartaapi}/jakarta/inject/Named.html[Named] 注解来支持这一用例。

== 按名称限定

要按名称限定，请使用 link:{jakartaapi}/jakarta/inject/Named.html[Named] 注解。例如，考虑以下类：

snippet::io.micronaut.docs.inject.qualifiers.named.Engine,io.micronaut.docs.inject.qualifiers.named.V6Engine,io.micronaut.docs.inject.qualifiers.named.V8Engine,io.micronaut.docs.inject.qualifiers.named.Vehicle[tags="class",indent=0]

<1> `Engine` 接口定义了公共契约
<2> `V6Engine` 类是第一个实现
<3> `V8Engine` 类是第二个实现
<4> link:{jakartaapi}/jakarta/inject/Named.html[jakarta.inject.Named] 注解表明需要 `V8Engine` 实现
<5> 调用 start 方法将输出：`"Starting V8"`

Micronaut 框架能够在上一个示例中注入 `V8Engine`，原因是：

`@Named` 限定符值（`v8`）+ 被注入类型的简单名称（`Engine`）==（不区分大小写）== 类型为 `Engine` 的 bean 的简单名称（`V8Engine`）

您也可以在 bean 的类级别声明 link:{jakartaapi}/jakarta/inject/Named.html[@Named]，以显式定义该 bean 的名称。

== Primary 与 Secondary bean

api:context.annotation.Primary[] 是一个限定符，当存在多个接口实现时，它表明该 bean 是应被选中的 primary bean。

考虑以下示例：

snippet::io.micronaut.docs.context.annotation.primary.ColorPicker[tags="clazz", indent=0]

以下类实现了 `ColorPicker`：

snippet::io.micronaut.docs.context.annotation.primary.Green[tags="imports,clazz", indent=0, title="The Primary Bean"]

`Green` bean 类实现了 `ColorPicker` 并标注了 `@Primary`。

snippet::io.micronaut.docs.context.annotation.primary.Blue[tags="imports,clazz", indent=0, title="Another Bean of the Same Type"]

`Blue` bean 类也实现了 `ColorPicker`，因此在注入 `ColorPicker` 接口时您会有两个可能的候选。由于 `Green` 是 primary，它总是会被优先选用。

snippet::io.micronaut.docs.context.annotation.primary.TestController[tags="clazz", indent=0]

<1> 虽然存在两个 `ColorPicker` bean，但由于 `@Primary` 注解，注入的是 `Green`。

如果存在多个可能的候选且未定义 `@Primary`，将抛出 api:context.exceptions.NonUniqueBeanException[]。

除 `@Primary` 外，还有 api:context.annotation.Secondary[] 注解，其效果相反，可用于降低某个 bean 的优先级。

TIP: 更多内容请参阅 https://guides.micronaut.io/latest/micronaut-patterns-composite.html[Micronaut 模式 - Composite] 指南。
