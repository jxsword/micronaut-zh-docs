与 Spring 和 Grails 一样，Micronaut 框架提供了用于调度后台任务的 api:scheduling.annotation.Scheduled[] 注解。

TIP: 更多信息请参阅 https://guides.micronaut.io/latest/micronaut-scheduled.html[在 Micronaut 应用中调度周期任务] 指南。

== 使用 @Scheduled 注解

api:scheduling.annotation.Scheduled[] 注解可以添加到 bean 的任何方法上，您应当设置 `fixedRate`、`fixedDelay` 或 `cron` 成员之一。调度功能需要 Micronaut Context 依赖：

dependency::micronaut-context[]

`micronaut-context` 是 `micronaut-http` 的传递依赖。如果您使用 Micronaut HTTP 运行时，您的项目已经包含 `Micronaut-context` 依赖。

NOTE: 请记住，bean 的作用域会影响行为。`@Singleton` bean 在每次执行调度方法时共享状态（实例的字段），而对于 `@Prototype` bean，每次执行都会创建新实例。

== 配置调度任务线程池

`@Scheduled` 执行的任务默认在 link:{jdkapi}/java.base/java/util/concurrent/ScheduledExecutorService.html[ScheduledExecutorService] 上运行，其线程数配置为可用处理器数的两倍。

您可以在配置文件（例如 `application.yml`）中配置该线程池：

//TODO: Move YAML snippet to ExecutorServiceConfigSpec
[configuration,title="Configuring Scheduled Task Thread Pool"]
----
micronaut:
  executors:
    scheduled:
      type: scheduled
      core-pool-size: 30
----

== 处理异常

默认情况下，Micronaut 框架包含一个 api:io.micronaut.scheduling.DefaultTaskExceptionHandler[] bean，它实现 api:io.micronaut.scheduling.TaskExceptionHandler[] 接口，在调用调度任务出错时仅记录该异常。

如果您有自定义需求，可以用自己的实现替换该 bean（例如发送电子邮件，或关闭上下文以快速失败）。为此，请编写您自己的 api:io.micronaut.scheduling.TaskExceptionHandler[] 并用 `@Replaces(DefaultTaskExceptionHandler.class)` 标注。
