自 Micronaut Framework 版本 4 起，https://projectreactor.io[Project Reactor] 集成不再自动捕获状态。Micronaut Framework 用户需要手动扩展传播上下文。

在版本 4 之前，Micronaut Framework 要求对每个响应式操作符进行插桩以捕获当前状态来传播它。这带来了不必要的开销，迫使我们维护复杂的 Reactor 操作符插桩。

自 3.5.0 起，Reactor-Core 内嵌了对 `io.micrometer:context-propagation` SPI 的支持。通过引入 https://micrometer.io/docs/contextPropagation[Micrometer Context Propagation] 依赖可以实现相同的线程本地传播。

框架会自动将 `PropagatedContext` 添加到 Project Reactor 的上下文中，供拦截器与 HTTP 过滤器使用。您可以通过工具类 api:core.async.propagation.ReactorPropagation[] 访问它。

NOTE: api:core.async.propagation.ReactorPropagation[] 是一个实验性类，未来可能变化。

可以使用 https://micrometer.io/docs/contextPropagation[Micrometer Context Propagation]，Reactor 支持用它传播与恢复线程本地上下文。

要启用它，请包含依赖：

dependency:context-propagation[groupId="io.micrometer",scope="compile"]

之后，所有线程本地传播的元素都可以恢复其线程本地值。

NOTE: 线程本地值是只读的。要修改它们，需要更改 `PropagatedContext` 实例并将其放入 Reactor 的上下文。

要在响应式链的中途添加上下文，可以像下面这样操作：

snippet::io.micronaut.docs.propagation.reactor.HelloController[tags="imports,example", indent=0]

<1> 获取已修改的当前上下文，例如通过 `PropagatedContext.get().plus(...)` 等。
<2> 将上下文添加进响应式链。

如果类路径上有 Micrometer Context Propagation 但您不想使用它，请应用以下配置：

.在 Reactor 中禁用 Micrometer Context Propagation
[configuration]
----
reactor:
    enable-automatic-context-propagation: false
----
