=== 流式客户端与响应类型

上一节定义的示例期望服务器以 JSON 对象流响应，且内容类型为 `application/x-json-stream`。例如：

.一个 JSON 流
[source,json]
----
{"title":"The Stand"}
{"title":"The Shining"}
----

原因很简单：一系列 JSON 对象实际上并不是有效 JSON，因此响应内容类型不能是 `application/json`。要使 JSON 有效，它必须返回一个数组：

.一个 JSON 数组
[source,json]
----
[
    {"title":"The Stand"},
    {"title":"The Shining"}
]
----

不过，Micronaut 客户端既支持通过 `application/x-json-stream` 流式传输单个 JSON 对象，也支持以 `application/json` 定义的 JSON 数组。

如果服务器返回 `application/json` 且返回了非单一 rs:Publisher[]（例如 Reactor 的 reactor:Flux[] 或 RxJava 的 rx:Flowable[]），客户端会在数组元素可用时流式传输它们。

=== 流式客户端与读取超时

从服务器流式读取响应时，底层 HTTP 客户端不会应用 api:http.client.HttpClientConfiguration[] 的默认 `readTimeout` 设置（默认 10 秒），因为流式响应的读取间隔可能与普通读取不同。

取而代之，由 `read-idle-timeout` 设置（默认 5 分钟）决定连接空闲多长时间后关闭。

如果您从条目间隔超过 5 分钟的服务器流式读取数据，应调整 `readIdleTimeout`。配置文件（例如 `application.yml`）中的以下配置演示了做法：

.调整 readIdleTimeout
[configuration]
----
micronaut:
  http:
    client:
      read-idle-timeout: 10m
----

上例将 `readIdleTimeout` 设置为 10 分钟。

=== 流式服务器发送事件

Micronaut 框架提供了由接口 api:http.client.sse.SseClient[] 定义的 Server Sent Events（SSE）原生客户端。

您可以使用该客户端从任何发出 SSE 事件的服务器流式读取 SSE 事件。

NOTE: 虽然 SSE 流通常由浏览器 `EventSource` 消费，但某些情况下您可能希望通过 api:http.client.sse.SseClient[] 消费 SSE 流，例如在单元测试中，或当 Micronaut 服务充当另一个服务的网关时。
