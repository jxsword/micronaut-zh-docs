==== 获取 HttpClient

有几种方式可以获得 api:http.client.HttpClient[] 的引用。最常见的是使用 api:http.client.annotation.Client[] 注解。例如：

.注入 HTTP 客户端
[source,java]
----
@Client("https://api.twitter.com/1.1") @Inject HttpClient httpClient;
----

上例注入了一个面向 Twitter API 的客户端。

[source,kotlin]
----
@field:Client("\${myapp.api.twitter.url}") @Inject lateinit var httpClient: HttpClient
----

上面的 Kotlin 示例注入了一个使用配置路径、面向 Twitter API 的客户端。注意 `"\${path.to.config}"` 上必需的转义（反斜杠），这是 Kotlin 字符串插值所要求的。

api:http.client.annotation.Client[] 注解还是一个自定义作用域，管理 api:http.client.HttpClient[] 实例的创建并确保应用关闭时它们被停止。

传给 api:http.client.annotation.Client[] 注解的值可以是以下之一：

* 绝对 URI，例如 `https://api.twitter.com/1.1`
* 相对 URI——此时目标服务器就是当前服务器（便于测试）
* 服务标识符。有关该主题的更多信息，请参阅 <<serviceDiscovery,服务发现>> 一节。

创建 `HttpClient` 的另一种方式是使用 api:http.client.HttpClient[] 的静态 `create` 方法，但不推荐这种方式，因为您必须确保手动关闭客户端，而且当然不会为创建的客户端发生依赖注入。

==== 执行 HTTP GET

使用 `HttpClient` 时一般有两个值得关注的方法。第一个是 `retrieve`，它执行 HTTP 请求并以您请求的类型（默认为 `String`）以 `Publisher` 形式返回响应体。

`retrieve` 方法接受一个 api:http.HttpRequest[] 或您希望请求的端点的 `String` URI。

==== 调试/追踪 HTTP 客户端

要调试 HTTP 客户端发送与接收的请求，您可以在 `logback.xml` 文件中启用追踪日志：

.logback.xml
[source,xml]
----
<logger name="io.micronaut.http.client" level="TRACE"/>
----

==== 客户端特定的调试/追踪

要启用客户端特定的日志记录，您可以为所有 HTTP 客户端配置默认 logger。您还可以使用 <<_client_specific_configuration,客户端特定配置>> 为不同客户端配置不同的 logger。例如，在配置文件（例如 `application.yml`）中：

[configuration]
----
micronaut:
  http:
    client:
      logger-name: mylogger
    services:
      otherClient:
        logger-name: other.client
----

然后在 `logback.xml` 中启用日志记录：

.logback.xml
[source,xml]
----
<logger name="mylogger" level="DEBUG"/>
<logger name="other.client" level="TRACE"/>
----

==== 解码其他内容类型

如果您通信的服务器使用非 JSON 的自定义内容类型，默认情况下 Micronaut 的 HTTP 客户端不知道如何解码该类型。

要解决此问题，将 api:http.codec.MediaTypeCodec[] 注册为 bean，它会被自动拾取并用于解码（或编码）消息。
