[[serverlessFunctions]]
Serverless 架构要求独特的开发方式——在这类架构中，您部署的函数完全由云环境托管，并在临时进程中执行。

Grails 和 Spring 等传统框架并不真正适合这种场景，因为低内存消耗和快速启动时间至关重要：函数即服务（FaaS）服务器通常会通过一次冷启动（cold start）把您的函数启动并运行一段时间，然后保持其热身状态。

Micronaut 的编译期方法、快速启动时间和低内存占用使其成为开发函数的理想之选。Micronaut 框架为开发和部署函数到 AWS Lambda、Google Cloud Function、Azure Function 以及任何支持以容器方式运行函数的 FaaS 系统（例如 OpenFaaS、Rift 或 Fn）提供了专门支持。

使用 Micronaut 编写函数通常有以下两种方式：

. 使用函数平台原生 API 编写的低层函数
. 高层函数：您只需像在典型 Micronaut 应用中那样定义控制器，然后部署到函数平台。

前者的启动时间开销略低，通常用于非 HTTP 函数，例如监听事件的函数或后台函数。

后者仅适用于 HTTP 函数，适合希望从现有应用中切出一部分并将其部署为 Serverless 函数的用户。如果冷启动性能是需要关注的问题，建议您为该选项考虑使用 GraalVM 构建 native image。
