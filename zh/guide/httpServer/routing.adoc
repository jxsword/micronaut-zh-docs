== URI 路径

`@Controller` 注解的值是一个 https://tools.ietf.org/html/rfc6570[RFC-6570 URI 模板]，因此您可以使用 URI 模板规范定义的语法在路径中嵌入 URI 变量。

NOTE: 许多其他框架（包括 Spring）都实现了 URI 模板规范

实际实现由 api:http.uri.UriMatchTemplate[] 类处理，该类扩展了 api:http.uri.UriTemplate[]。

您可以在应用中使用该类来构建 URI，例如：

<2> 使用 `expand` 方法将模板展开为 URI

URI 变量可以通过方法参数引用。当路径变量与方法参数名匹配时，它们会自动绑定在一起。如果您想使用不同的名称，或为缺失的 URI 变量指定默认值，可以使用 link:{api}/io/micronaut/http/annotation/PathVariable.html[PathVariable] 注解。下面的示例演示了这些选项：

下表提供了 URI 模板及其匹配内容的示例：

.URI 模板匹配
|===
|模板 |说明|匹配的 URI

|`/books/{id}`
| 简单匹配
| `/books/1`

|`/books/{id:2}`
| 最多两个字符的变量
| `/books/10`

|`/books{/id}`
| 可选 URI 变量
| `/books/10` 或 `/books`

| `/book{/id:[a-zA-Z]+}`
| 带正则的可选 URI 变量
| `/books/foo`

| `/books{?max,offset}`
| 可选查询参数
| `/books?max=10&offset=10`

| `/books{/path:.*}{.ext}`
| 带扩展名的正则路径匹配
| `/books/foo/bar.xml`

|===

== URI 保留字符匹配

默认情况下，https://tools.ietf.org/html/rfc6570[RFC-6570 URI 模板] 规范定义的 URI 变量不能包含 `/`、`?` 等保留字符。

如果您想匹配或展开完整路径，这可能是个问题。根据 https://tools.ietf.org/html/rfc6570#section-3.2.3[规范第 3.2.3 节]，您可以使用 `+` 运算符进行保留字符展开或匹配。

例如，URI `/books/{\+path}` 同时匹配 `/books/foo` 与 `/books/foo/bar`，因为 `+` 表示变量 `path` 应包含保留字符（此处为 `/`）。

== 路由条件

api:http.annotation.RouteCondition[] 注解允许您定义一个条件，该条件必须求值为 `true`，路由才能匹配请求。条件以 Micronaut 表达式语言（EL）表达式指定，并在请求时求值。

在表达式中，可以使用一个 `request` 变量，它引用当前的 api:http.HttpRequest[]。

这对于基于查询参数、请求头或请求的其他方面来路由请求很有用。例如，您可以使用 `@RouteCondition` 根据查询参数的值将请求路由到不同的方法：

snippet::io.micronaut.docs.server.routing.RouteConditionController[tags="imports,class", indent=0, title="Route Condition Example"]

<1> 路由条件表达式求值判断 `v` 查询参数是否等于 `2`。如果等于，请求被路由到 `helloV2()`；如果不等于，路由不匹配，请求落回 `helloV1()`。

NOTE: api:http.annotation.RouteCondition[] 注解只适用于服务器端路由，放在声明式 HTTP 客户端路由上会被忽略。

TIP: 表达式中的 `request` 变量是 api:http.HttpRequest[] 的实例。您可以通过 `request.headers` 访问请求头，通过 `request.parameters` 访问查询参数，并按需访问其他请求属性。

== @Options

<<cors, CORS>> 支持处理 OPTIONS 预检请求。但是，如果您想在没有 Origin HTTP 头的情况下分发 OPTIONS 请求，可以通过以下方式启用：

[configuration]
----
micronaut:
  server:
    dispatch-options-requests: true
----

== 路由编译期校验

Micronaut 框架支持使用校验库在编译期验证路由参数。开始使用时，请将 `micronaut-http-validation` 依赖添加到构建中：

dependency:io.micronaut:micronaut-http-validation[scope='annotationProcessor']

类路径上有正确的依赖后，路由参数将在编译期自动检查。如果满足以下任一条件，编译将失败：

* {blank}
 URI 模板包含一个可选变量，但方法参数未标注 `@Nullable` 或不是 `java.util.Optional`。

一个可选变量是指即使值不存在，路由也能匹配 URI 的变量。例如 `/foo{/bar}` 匹配对 `/foo` 与 `/foo/abc` 的请求。非可选的变体则是 `/foo/{bar}`。更多信息请参阅 <<_uri_path_variables,URI 路径变量>> 一节。

* {blank}
 URI 模板包含一个方法参数中缺失的变量。

NOTE: 要禁用路由编译期校验，请设置系统属性 `-Dmicronaut.route.validation=false`。对于使用 Gradle 的 Java 与 Kotlin 用户，从 `annotationProcessor`/`kapt` 作用域中移除 `micronaut-http-validation` 依赖也可以达到同样效果。

== 路由非标准 HTTP 方法

`@CustomHttpMethod` 注解为客户端或服务器支持非标准 HTTP 方法。像 https://tools.ietf.org/html/rfc4918[RFC-4918 Webdav] 这样的规范需要额外的方法，例如 REPORT 或 LOCK。

.RoutingExample
[source,java]
----
@CustomHttpMethod(method = "LOCK", value = "/{name}")
String lock(String name)
----

该注解可以用在标准方法注解可用的任何地方，包括控制器和声明式 HTTP 客户端。
