=== 以响应式方式写响应数据

Micronaut 的 HTTP 服务器支持通过返回一个发出可编码到 HTTP 响应的对象的 rs:Publisher[]，分块写入响应数据。

下表汇总了示例返回类型签名以及服务器处理它们时的行为：

|===
|返回类型 | 说明

|`Publisher<String>`
|一个以 String 形式发出每个内容块的 rs:Publisher[]
|`Flux<byte[]>`
|一个以 `byte[]` 形式无阻塞地发出每个内容块的 reactor:Flux[]
|`Flux<ByteBuf>`
|一个以 Netty `ByteBuf` 形式发出每个块的 Reactor `Flux`
|`Flux<Book>`
|发出 POJO 时，默认无阻塞地将每个发出的对象编码为 JSON

|`Flowable<byte[]>`
|一个以 `byte[]` 形式无阻塞地发出每个内容块的 reactor:Flux[]
|`Flowable<ByteBuf>`
|一个以 Netty `ByteBuf` 形式发出每个块的 Reactor `Flux`
|`Flowable<Book>`
|发出 POJO 时，默认无阻塞地将每个发出的对象编码为 JSON

|===

返回响应式类型时，服务器使用 `chunked` 的 `Transfer-Encoding`，并持续写入数据，直到调用 rs:Publisher[] 的 `onComplete` 方法。

服务器从 rs:Publisher[] 请求单个条目，写入它，再请求下一个，从而控制背压。

NOTE: 订阅 rs:Publisher[] 可能引发的阻塞 I/O 工作，由其实现自行调度。

NOTE: 要使用 https://projectreactor.io[Project Reactor] 的 `Flux` 或 `Mono`，您需要在项目中添加 Micronaut Reactor 依赖以包含必要的转换器。

NOTE: 要使用 https://github.com/ReactiveX/RxJava[RxJava] 的 `Flowable`、`Single` 或 `Maybe`，您需要在项目中添加 Micronaut RxJava 依赖以包含必要的转换器。

=== 执行阻塞 I/O

某些情况下，您可能希望集成一个不支持非阻塞 I/O 的库。

==== Writable

在这种情况下，您可以从任何控制器方法返回 api:core.io.Writable[] 对象。api:core.io.Writable[] 接口有多种签名，允许写入传统的阻塞流，例如 link:{jdkapi}/java.base/java/io/Writer.html[Writer] 或 link:{jdkapi}/java.base/java/io/OutputStream.html[OutputStream]。

返回 api:core.io.Writable[] 时，阻塞 I/O 操作会转移到 I/O 线程池，因此 Netty 事件循环不会被阻塞。

TIP: 有关如何配置 I/O 线程池以满足应用需求，请参阅 <<threadPools,服务器线程池>> 配置一节。

<2> 返回空的 `Mono` 会触发 404（Not Found）响应。

NOTE: 以空的 `Publisher` 或 `Flux` 响应是流式响应，当内容类型为 JSON 时会返回空数组。要禁用流式传输，请用 api:core.async.annotation.SingleResult[] 标注该方法。
