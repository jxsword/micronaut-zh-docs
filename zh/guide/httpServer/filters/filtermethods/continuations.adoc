请求过滤器可以定义一个特殊的 api:http.filter.FilterContinuation[] 参数，以获得对下游执行更多的控制，并在其完成后运行后续操作。例如，上面的 `TraceFilter` 可以用单个请求过滤器表达：

snippet::io.micronaut.docs.server.filters.filtermethods.continuations.TraceFilter[tags="doFilter", indent=0, title="Single request filter"]

<1> 请求过滤器声明一个 api:http.filter.FilterContinuation[] 参数。continuation 将返回一个 api:http.MutableHttpResponse[]
<2> 请求处理完成后，过滤器调用阻塞的 `proceed` 来运行下游过滤器与控制器
<3> 当下游处理完成后，过滤器向 continuation 返回的响应添加 `X-Trace-Enabled` 请求头
<4> 整个过滤器在工作线程上执行，以避免在 `proceed` 调用中阻塞事件循环

IMPORTANT: 对 `FilterContinuation.proceed` 的调用默认是阻塞的，因此绝不应在事件循环上进行。此类过滤器应如上所述在工作线程上运行。或者，也可以将 continuation 声明为返回响应式类型（`Publisher<HttpResponse<?>>`），以类似于旧的 api:http.filter.FilterChain[] API 的方式异步进行。
