如果您需要对请求处理有更多控制，可以编写一个接收完整 api:io.micronaut.http.HttpRequest[] 的方法。

实际上，有多个更高级别的接口可以绑定到控制器方法参数，包括：

.可绑定的 Micronaut 接口
|===
|接口 |说明 |示例

|api:io.micronaut.http.HttpRequest[]
|完整的 `HttpRequest`
|`String hello(HttpRequest request)`

|api:io.micronaut.http.HttpHeaders[]
|请求中存在的所有 HTTP 请求头
|`String hello(HttpHeaders headers)`

|api:io.micronaut.http.HttpParameters[]
|请求中存在的所有 HTTP 参数（来自 URI 变量或请求参数）
|`String hello(HttpParameters params)`

|api:io.micronaut.http.cookie.Cookies[]
|请求中存在的所有 cookie
|`String hello(Cookies cookies)`
|===

IMPORTANT: 如果需要请求体，api:io.micronaut.http.HttpRequest[] 应声明为以具体泛型类型参数化，例如 `HttpRequest<MyClass> request`。否则请求体可能无法从请求中获取。

此外，要对发出的 HTTP 响应有完全控制，可以使用 api:io.micronaut.http.HttpResponse[] 类的静态工厂方法，它们返回 api:io.micronaut.http.MutableHttpResponse[]。

<1> 该方法映射到 URI `/hello` 并接受一个 api:io.micronaut.http.HttpRequest[]

IMPORTANT: 通常 api:io.micronaut.http.context.ServerRequestContext[] 在响应式流中可用，但推荐的方式是像前一个示例那样将请求作为参数接收。如果下游方法需要请求，应将其作为参数传递给这些方法。有些情况下上下文不会传播，因为使用了其他线程来发出数据。

对于 Project Reactor 用户，替代 ServerRequestContext 的方案是使用 Project Reactor 的上下文特性来检索请求。由于 Micronaut 框架使用 Project Reactor 作为其默认的响应式流实现，Project Reactor 用户可以从上下文中访问请求而获益。例如：
