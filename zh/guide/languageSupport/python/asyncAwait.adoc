Java 调用返回的任何 `CompletionStage` 或 `Publisher` 都是可等待的，不限于注入 bean 的值：`await Mono.just(value)` 与 `await Mono.from_(publisher).toFuture()` 都可以工作。

await 失败时会抛出 Java 异常本身，与等效的阻塞调用一样，因此 `except HttpClientResponseException` 处理被等待的客户端调用的方式与处理 `toBlocking()` 完全相同。与阻塞式 Java 调用一样，`except Exception` 捕获不到 Java 异常：请捕获 Java 类型、像 `java.lang.RuntimeException` 这样的 Java 父类，或 `BaseException`。保存在 future 上的失败（`future.exception()`，或 `asyncio.gather(..., return_exceptions=True)` 的结果）是一个 `micronaut_asyncio.MicronautJavaException`，其 `java_exception` 属性是 Java 异常。asyncio 网络 API 的网络故障会以 asyncio 代码期望的 `OSError` 子类抛出（参见 <<asyncioNetworking>>）。

被等待值背后的协程抛出的 Python 异常——例如带有 `@Cacheable` 等 AOP 通知的 bean 的 `async def` 方法——会以原始异常对象的形式抛出，而不是以携带它穿过拦截器链的 Java 异常的形式，因此 `except MyError` 能匹配它。

对于 `Publisher`，Micronaut 请求一个条目、以第一个条目完成等待并取消订阅。若发布者以空完成，被等待的值是 `None`；若它发出错误信号，则等待失败。多条目的 `Flux` 值不会隐式收集成列表。需要全部发出条目时，请使用 `collectList()` 这类响应式操作符，或按 <<asyncioStreaming>> 所述以 `async for` 逐个消费条目。

实现了声明返回 `Publisher`、`Mono` 或 `Flux` 的 Java 方法的 `async def`，会被适配到该类型，且协程只在发布者被订阅时才开始运行：它所等待的发布者在订阅者的 Reactor 上下文中订阅（例如由 `@Transactional` 调用方启动的响应式事务），而协程的每一步都在该订阅者的 `PropagatedContext` 中运行，无论由哪个任务或线程恢复它。由此可得：无人订阅时协程从不运行（Python 会警告协程从未被 await）；运行它的事件循环是订阅线程的事件循环，因此 `subscribeOn` 决定由哪个循环运行协程；首次订阅的结果会与后续订阅者共享。声明为 `CompletionStage` 的方法则在方法被调用时即时启动协程，使用调用方的 `PropagatedContext`。

asyncio 桥接支持默认启用。可用以下配置禁用：

[configuration]
----
micronaut:
  python:
    asyncio:
      enabled: false
----
