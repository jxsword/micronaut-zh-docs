[[bootstrap]]
大多数应用配置都存储在您的配置文件（例如 `application.yml`）、环境特定文件（如 `application-{environment}.{extension}`）、环境与系统属性等之中。
这些内容配置了应用上下文。
但在应用启动期间、应用上下文创建之前，可以创建一个「bootstrap」上下文来存储必要的配置，用于为主上下文检索额外的配置。通常，该额外配置位于某个远程源中。

bootstrap 上下文根据以下条件启用。这些条件按以下顺序检查：

- 如果设置了 api:context.env.Environment#BOOTSTRAP_CONTEXT_PROPERTY[micronaut.bootstrap.context] 系统属性，该值决定是否启用 bootstrap 上下文。
- 如果设置了应用上下文构建器选项 api:context.ApplicationContextBuilder#bootstrapEnvironment[bootstrapEnvironment]，该值决定是否启用 bootstrap 上下文。
- 如果存在 api:context.env.BootstrapPropertySourceLocator[] bean，则启用 bootstrap 上下文。通常这来自 `micronaut-discovery-client` 依赖。如果您为分布式配置提供了自定义的 api:discovery.config.ConfigurationClient[]，请确保存在该依赖，以便加载 bootstrap/分布式配置基础设施。

在应用上下文配置属性解析之前必须存在的配置属性（例如使用分布式配置时）存储在 bootstrap 配置文件中。一旦确定启用了 bootstrap 上下文（如上所述），就会按照与常规应用配置相同的规则读取 bootstrap 配置文件。
详情请参阅 <<propertySource,属性源>> 文档。唯一的区别是前缀（`bootstrap` 而不是 `application`）。

文件名前缀 `bootstrap` 可以通过系统属性 link:{api}/io/micronaut/context/env/Environment.html#BOOTSTRAP_NAME_PROPERTY[micronaut.bootstrap.name] 进行配置。

NOTE: bootstrap 上下文的配置会自动延续到主上下文，因此没有必要在主上下文中重复这些配置属性。此外，bootstrap 上下文配置的优先级高于主上下文，这意味着如果同一个配置属性同时出现在两个上下文中，将优先采用 bootstrap 上下文中的值。

这意味着如果一个配置属性在两处都需要，它应该放在 bootstrap 上下文配置中。

有关与常见分布式配置解决方案集成的列表，请参阅文档中 <<distributedConfiguration,分布式配置>> 一节。

=== Bootstrap 上下文 bean

要让 bean 能够在 bootstrap 上下文中解析，必须用 ann:context.annotation.BootstrapContextCompatible[] 注解标注它。如果某个 bean 未标注该注解，则它将无法在 bootstrap 上下文中解析。通常，任何参与检索分布式配置过程的 bean 都需要标注。

例如，如果您实现的自定义分布式配置在 bootstrap 期间解析，则它依赖的任何支持 bean 都必须与 bootstrap 兼容，并且应用必须包含发现客户端基础设施，通常通过添加 `io.micronaut.discovery:micronaut-discovery-client` 依赖实现。
